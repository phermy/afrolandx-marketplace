---
name: SEO and performance measurement
description: How to interpret the agreed implementation budget and preserve public-only server content
---

Treat the 300 KB target used for this SEO work as compressed first-load application JavaScript, including the shared entry and the route's entire static dependency graph. Report raw size separately when comparing against an uncompressed target. Interaction-only modules are not part of that first-load measurement; do not hide immediate or idle-triggered downloads to make a budget appear smaller.

**Why:** The previous single bundle loaded dashboards for public visitors. Splitting one large file into many immediately downloaded files would not actually solve that problem.

**How to apply:** Compare complete route loads, not individual chunks. If the user subsequently specifies a raw-size or whole-network budget, follow that newer definition.

Keep request-time public catalog content behind the same approval gates as public shopping APIs, and preserve NGN offers. Never pre-render private account, payment or contact records.

**Why:** Static catalog snapshots can retain withdrawn listings or stale availability, and publicly rendered documents are visible without signing in.

**How to apply:** Future rendering or caching work must preserve public-data ownership and refresh approval/availability changes rather than adding an authentication bypass.
